# 0007. 收敛班级生命周期与在读学籍级联为教学班级全生命周期协调器

## 状态
Accepted

## 背景与决策
在原有系统中，教学班级（Class）的状态管理与生命周期流转处于浅层平铺变更（Shallow Update）状态：
1. **孤儿课包与幽灵学籍**：前端 `classManagement.vue` 与服务端 `educational.service.ts` 在执行班级状态变更时，仅仅执行了 `prisma.class.update({ where: { id }, data: { status: 'completed' } })`。班级结业或解散后，名下在读学员的课包 `studentCoursePackage.classId` 依然死死指向已结课的班级，未消完课时无法回退到待分班池，也无法批量顺延升班；学员的主体学籍状态 `student.status` 依然挂着 `in_class`，造成系统中的“幽灵在读”状态；
2. **幽灵未来排课占用**：班级虽然标记结课或解散，但排课系统预先生成的未发生未来排课日程（`status: scheduled`）依然霸占着校区物理教室与教师的时段工时，导致排课冲突引擎（Collision Engine）频繁发生伪冲突；
3. **教学与财务防腐屏障缺失**：过去教务在列表删除班级时，若已有考勤消课记录则简单报错阻断，教务缺乏对已开课班级合规撤班解散的业务通路；
4. **升班与合班并发班容超卖**：批量升班或多班合并时，缺少行级排他锁，多个班级并发并入同一目标班级容易导致班容击穿（超编）。

我们决定在服务端建立教务核心深模块 `ClassLifecycleCoordinator`，以「面向高频教务任务工步（`activateClass`, `completeClass`, `cancelClass`, `mergeClasses`）」为主干骨架，深度融合「零写副作用仿真预演（`previewOperation`）」与「不可变审计回执（`ClassLifecycleReceipt`）」，内部闭环 5 大业务不变量：
- 班级状态机合法单向跃迁守卫；
- 在读学员课包原子处置（回退待分班池 `classId=null` / 批量升班换绑）；
- 学籍状态机原子自愈（`in_class` -> `normal` / `graduated`）；
- 未执行未来排课日程批量物理注销与物理教室/教师时段即时释放；
- 历史已点名考勤日程 100% 锁死防腐（严禁物理删除）；
- 目标班级行级 CAS 班容并发锁（`currentStudentCount + N <= capacity`）。

## 评估过的备选方案
- **备选方案 A（极简 CQS 入口方案）**：对外仅暴露 `previewTransition` 与 `executeTransition` 两个方法，入参通过弱类型或平铺字典声明意图。被否决，因为不同状态跃迁所需参数高度分化（开班无需目标班级，升班强依赖目标班级），平铺参数在调用端缺少直观的领域动词和编译期校验。
- **备选方案 B（纯声明式状态机与事件驱动方案）**：通过 Discriminated Union 联合类型驱动，每次调用需要构造复杂的嵌套 Intent 对象。被否决，对于日常高频的“招生完成点击开班”或“一键结课”，过多的结构体嵌套增加了教务前端调用的样板代码与组装负担。
- **入选方案（实用主义高韧性融合深模块）**：以方案 C 的任务型语义工步为接缝，融合方案 A 的二阶段只读仿真预检能力，以及方案 B 的不可变审计凭证（SHA-256 数据指纹），兼顾调用端直观人体工学、预演防错与集团级审计合规。

## 结果与收益
- **课包与学籍彻底自洽**：结业与解散时课包 100% 安全处置，学籍自动自愈，彻底杜绝孤儿课包与幽灵在读状态。
- **教学资源即时出清**：班级结课后未来未上课次自动撤销，物理教室与讲师工时 100% 释放，消除排课系统冲突矩阵的幽灵占用。
- **历史消课考勤绝对防腐**：历史已消课日程与学员学情档案永久锁死，保全反结课冲正与退费财务审计证据链。
- **班容安全零击穿**：行级 CAS 锁确保批量升班与合并时绝不超编。
- **测试表面高度收敛**：测试端直接跨过生命周期协调器的高阶工步进行场景穿透，消除对 UI 碎片化请求的脆弱依赖。
